## Featured Projects

### 🔗 [Linkly](https://github.com/adocxwork/linkly) — Enterprise-Grade Creator Identity Platform
[![Live](https://img.shields.io/badge/Live-success?style=flat-square&logo=vercel)](https://linkly-plum.vercel.app/) [![Spring Boot](https://img.shields.io/badge/Spring_Boot-3-6DB33F?style=flat-square&logo=spring)](https://github.com/adocxwork/linkly) [![Redis](https://img.shields.io/badge/Redis-Streams-DC382D?style=flat-square&logo=redis)](https://github.com/adocxwork/linkly) [![PostgreSQL](https://img.shields.io/badge/PostgreSQL-16-336791?style=flat-square&logo=postgresql)](https://github.com/adocxwork/linkly)

A highly scalable, distributed platform engineered to handle unpredictable viral traffic surges. Built with Java 21, Spring Boot, and an Event-Driven Analytics Engine using Redis Streams to decouple heavy writes from critical read-paths. Features sub-millisecond read latencies with Upstash Redis, Bucket4j rate limiting, Flyway migrations, and strict JWT security routed via a Vercel Edge Reverse Proxy.

**[Live Demo →](https://linkly-plum.vercel.app/)** &nbsp;·&nbsp; **[Source →](https://github.com/adocxwork/linkly)**

### 🛡️ [Resilient Checkout API](https://github.com/adocxwork/resilient-checkout-api) — Fault-Tolerant Distributed Checkout Engine
[![Spring Boot](https://img.shields.io/badge/Spring_Boot-3.3-6DB33F?style=flat-square&logo=spring)](https://github.com/adocxwork/resilient-checkout-api) [![PostgreSQL](https://img.shields.io/badge/PostgreSQL-15-336791?style=flat-square&logo=postgresql)](https://github.com/adocxwork/resilient-checkout-api) [![Resilience4j](https://img.shields.io/badge/Resilience4j-Circuit_Breaker-red?style=flat-square)](https://github.com/adocxwork/resilient-checkout-api)

An order processing API designed to systematically solve critical distributed e-commerce challenges during concurrent checkout operations. Built with Spring Boot and PostgreSQL to defend against duplicate billing via idempotent operations, inventory overselling via pessimistic locking (`SELECT ... FOR UPDATE`), cascading gateway failures via Resilience4j circuit breakers, and inconsistent states via background state machine reconciliation.

**[Source →](https://github.com/adocxwork/resilient-checkout-api)**
